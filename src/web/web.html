📖 两种接入模式的原理（点开阅读）

直连模式（443 · 原生 TLS）

浏览器 → PAC 判定 → 本地代理(21878) ── TLS隧道直达 ──→ 你的VPS(443) → 目标网站
                        纯净二进制协议，中间没有任何第三方

链路最短、延迟最低。但域名的 DNS 解析直接暴露 VPS 真实 IP， 且防火墙能看到"你 ↔ VPS"之间存在持续加密大流量。因此直连域名必须保持灰云（DNS only） ——灰云只做解析、不碰流量，私有协议才能直达。

CDN 模式（8443 · WebSocket over Cloudflare）

浏览器 → PAC 判定 → 本地代理(21878) ── WebSocket帧(藏在HTTPS里) ──→ Cloudflare边缘节点 ──→ 你的VPS(8443) → 目标网站
                                      ↑ 你和公网只接触CF的IP，VPS真实IP彻底隐藏 ↑

隧道字节被封装成 WebSocket 帧（普通网页长连接技术），外层是标准 HTTPS。 流量特征 = "访问一个普通网站的加密长连接"，且混入 Cloudflare 每天的海量正常流量中； 想封也只能封 CF（等于封掉半个互联网），所以 VPS IP 几乎无法被针对。代价：多一跳 CF，延迟略增。

为什么橙云域名不能直连、灰云域名不能 CDN？

橙云 = DNS 把域名解析到 CF，且 CF 强制七层代理——它只认识 HTTP/WebSocket， 纯 TLS 私有隧道会在 CF 处被掐断，所以直连必须用灰云域名（解析直达 VPS）。 CDN 模式的 WebSocket 握手本身就是标准 HTTP 升级，CF 认识，所以橙云域名专门给它用。

使用建议：

平时用 CDN 模式（IP 受保护、抗封锁）；CF 偶发抽风或维护时， 一键切直连模式应急。两个模式的服务端入口永远同时在线，切换只需几秒。

配置

直连地址?灰云域名或服务器IP:443。DNS 直接解析到 VPS，不能开 Cloudflare 橙云（橙云会强制七层代理，纯 TLS 隧道会被掐断）。直连模式走这个地址。
CDN地址?橙云域名:8443。域名需托管到 Cloudflare 并开启橙色云代理，流量封装成 WebSocket 混入 CF 正常流量，VPS 真实 IP 被隐藏、抗封锁，代价是多一跳延迟。
证书主域?仅用于 PAC 绕行：访问这个域名（及其子域）时不走隧道、直接连接。服务端实际签发证书的域名以服务器启动参数/issue-cert.sh 为准，这里改不会改变服务端证书。
本地端口?本机 SOCKS5/HTTP 代理监听端口（绑定 127.0.0.1），浏览器/应用把代理指向 127.0.0.1:此端口。面板会自动接管系统代理，一般不用改。
DNS 上游?本地 DNS 转发上游（逗号分隔 IP，按序尝试），设置后客户端在本机 127.0.0.1:53 提供 DNS：把系统/网卡 DNS 指向它，所有域名经隧道由 VPS 出口解析，本地解析 DNS 的应用（Android Studio/SDK Manager 等）不再拿到国内 CDN IP。提示：223.5.5.5 对 Google 系域名返回国内 CDN 节点（VPS 连不上），下载 dl.google.com 失败时改为 8.8.8.8。清空 = 关闭。
流量配额?仅用于面板显示"服务器流量"进度条。服务端真正的限额以其启动参数 -max-gb（server.conf 的 MAX_GB）为准，超限后服务端拒绝新隧道。
周期天数?流量统计周期天数，到期服务端自动清零重新计数。同样以服务端启动参数为准，这里仅用于显示剩余天数。
认证密码?两端必须一致的认证密码，也是面板调服务端管理 API 的凭证。「轮换」让服务端生成随机新密码并热生效，本面板自动重启客户端。密码错误时隧道会连不上（客户端表现为 EOF）。
代理域名?PAC 白名单：只有这些后缀的域名走隧道，其余全部直连。每行一个后缀（如 github.com 匹配其所有子域）。保存立即重建 PAC 生效。
代理 IP?额外指定走隧道的裸 IP，每行一个，支持 * 通配（如 1.2.3.4 或 52.10.*）。内网段（127/192.168/10）设计上永远直连，不受此清单影响。

pac 模式下仅清单内域名与「代理 IP」走隧道，其余直连；保存后立即重建 PAC。认证密码需与服务端一致，点「轮换」让服务端生成随机新密码并热生效（自动重启客户端）。证书主域仅用于 PAC 绕行，服务端证书域以其启动参数为准。

安全策略

认证失败封禁?同一 IP 认证失败 10 次（5 分钟窗口）封 30 分钟。调试认证/证书问题时临时关闭可避免测试连接被误封；重新开启前会先清空现存封禁名单。-

状态持久化在服务器数据目录 security.json，服务端重启后保持；调试完建议重新开启。

服务端证书

签发者?证书颁发机构。Let's Encrypt = 免费 ACME 真证书（浏览器/系统默认信任）；caotun = 自签兜底证书（客户端走 TOFU 指纹校验，安全性等同）。-
覆盖域名?证书保护的域名清单。客户端访问的直连/CDN 域名必须在此清单内（或走 TOFU）。-
过期时间?证书失效时刻。到期后客户端将无法建立新连接，需在服务器上重跑 issue-cert.sh 续期（acme.sh 的每日 cron 也会自动续）。-
剩余?距过期的天数。少于 15 天变黄提醒；acme.sh 的 cron 会在到期前自动续期。-

显示服务端正在使用的证书（正式/自签兜底）与有效期。证书由服务器上的定时脚本（issue-cert.sh）签发续期，服务端检测到文件变化会自动热加载，无需重启。

说明

· 访问代理服务器自身的域名/IP，或 192.168.*、10.*、127.* 等内网地址时不走隧道、直接连接：连代理自己不该再绕一圈代理；路由器/NAS 等内网设备也只有直连才通
· 密码由用户在"配置"卡自设（与服务端一致）；「轮换」经服务端管理 API 热更新双端
· 认证失败过多会触发服务端封禁 IP（管理 API 同样计入，防爆破）
· 日志写入 ~/.caotun/，自动轮转防止无限增长
